## Architecture Optimizations (Audit Findings)

### 1. Bundle AST Dependencies (Size & Speed)
- [x] Configure `tsup.config.ts` to bundle `unified`, `remark`, and `rehype` ecosystems.
- [x] Externalize only massive binaries/WASM (e.g., `playwright-core`, `shiki`).
- **Impact:** Eliminates thousands of `node_modules` files and saves ~150-300ms in file-system I/O during startup.

### 2. Mermaid.js Asset Decoupling (Size)
- [x] Move `mermaid` from `dependencies` to `devDependencies`.
- [x] Copy `mermaid.min.js` directly to `dist/assets/mermaid.min.js` during the build phase.
- [x] Inject the local asset in Playwright instead of relying on Node resolution.
- **Impact:** Shrinks production install footprint by ~3MB.

### 3. Parallelize Playwright Warming (Speed)
- [x] Initialize the Mermaid browser context concurrently with the main HTML browser context.
- [x] Use `Promise.all()` in `src/pdf/daemon.ts` to avoid synchronous blocking.
- **Impact:** Shaves 200-300ms off "Time-to-First-PDF" during batch processing.

### 4. Cache the Unified Processor (Speed)
- [x] Cache the initialized `unified().use(...)` instance across batch jobs with the same config.
- [x] Prevent rebuilding the 15+ plugin AST chain for every file.
- **Impact:** Eliminates CPU overhead per file during large batch conversions.

### 5. Singleton Shiki Highlighter (Speed)
- [x] Initialize `getHighlighter()` from `shiki` exactly once at the start of the CLI process.
- [x] Pass the active highlighter instance down into the AST plugin pipeline.
- **Impact:** Prevents heavy Oniguruma WASM binary re-initialization across multiple file conversions.
